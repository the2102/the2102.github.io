TASK & FORM

규제 사전검토

문서량은 적고 판단이 복잡합니다. 전부 컨텍스트에 실을 수 있어 검색(RAG)이 필요 없고, 필요한 것은 판단 순서와 기준을 매번 똑같이 적용하는 일입니다. 그래서 절차와 기준을 문서로 고정하는 스킬로 만들었습니다.

TASK (ii) · 웹앱

특허 아이디어 탐색

판단은 단순하지만 특허가 6,860건입니다. 한 번에 읽힐 수 없어 검색(키워드 + 의미)이 꼭 필요하고, 동료가 링크로 써야 하므로 웹앱으로 만들었습니다.

03

04

05

교차 판단

06

보고서 작성

v1 · 시험

판정은 모두 맞았지만, 판단기준에 없는 해석이 판정과 같은 톤으로 섞였습니다. "그리퍼는 로봇 KCs에 포함되지 않는다"처럼 근거 없는 단정도 1건 나왔습니다. 7강에서 본 misgrounded 인용과 같은 구조입니다.

v2 · 수정

근거 없는 해석은 💡추론·💡제안으로 표시하는 규칙을 추가했습니다. 시험이 판단기준 자체의 모호함(AI 기본법을 🟡 하나로 적어 실행마다 표기가 갈림)과 공백(팔 단품 KCs 보유 시 결합체 재신고 여부)도 드러내서 기준을 고쳤습니다.

v3 · 수정 · 재시험

받는 사람이 원문을 확인할 수 있게 근거 링크 표를 넣고, 표에 없는 주소는 만들지 않도록 했습니다. 링크는 모두 접속해 확인했고, 존재하지 않는 법령명은 사이트가 오류를 돌려준다는 점도 함께 확인했습니다. 재시험에서 v1 문제가 모두 해소됐습니다.

해도 되는가: 애매했던 점과 판단

애매한 점판단과 극복남은 위험
법률 자문처럼 보인다사전 점검 자료로 범위를 한정하고 고지 문구를 고정. 모든 판정에 근거 법령 링크, 확인 필요 항목은 결론에서 제외읽는 사람이 판정을 확정 결론으로 받아들일 수 있음
회사 제품 사양을 외부 AI에 넣어도 되나시험과 발표는 모두 가상 사양. 출시 전 실제 사양은 영업비밀이라 회사가 승인한 도구에서만 사용실무 도입에는 사내 승인 절차가 필요
법령이 바뀌면 틀린다판단기준에 기준일을 적고 보고서에 표시. 링크는 현행 법령으로 연결되므로 개정 확인을 권고기준을 갱신하는 담당과 주기가 정해지지 않음
ISO 등 유료 표준을 넣어도 되나저작물이라 원문은 넣지 않고 번호만 참조. 내용은 판정하지 않음협동운전 판단의 핵심이 유료 표준 안에 있음
AI가 링크나 조문을 지어낼 수 있다판단기준 표에 있는 링크만 쓰게 하고, 링크가 없으면 확인처만 적게 함표에 오기가 있으면 그대로 전파됨
누락하면 누가 책임지나해당 없음도 이유를 남겨 사람이 검토. 최종 판단은 인증기관·법무판단기준에 없는 제도는 스킬이 찾지 못함

# 로봇 규제·인증 사전검토

로봇 사양을 받아, 여러 법령을 가로질러 적용되는 규제·인증을 판정하고 의무 주체와 생애주기별로 정리한 사전검토 보고서를 만든다.

## 절차

1. **사양 확인**
   아래 항목을 확인한다. 빠진 항목이 판정을 바꾸면 사용자에게 한 번에 묶어서 묻는다. 판정에 영향이 없으면 묻지 않고 "가정"으로 적는다.
   - 형태(이동 방식, 매니퓰레이터 축 수), 질량, 최고속도
   - 운행·설치 장소(보도 / 실내 공공시설 / 사업장 / 가정), 사람과의 공간 공유 여부
   - 카메라, 무선통신, 배터리
   - AI 기능(자율주행 판단, 대화형 생성형 AI, 의료·재활 목적 등)
   - 판매 대상(B2B 사업장, 공공 서비스, 소비자)

2. **판단기준 읽기**
   `judgment-criteria.md`를 끝까지 읽는다. 판정은 이 문서의 기준만 근거로 한다.

3. **유형 판정**
   judgment-criteria.md 2절로 유형을 정한다. 둘 이상에 해당하면 모두 적용한다.

4. **항목별 판정**
   해당 유형 기준(3절)과 공통 레이어(4절)를 차례로 대 보고, 항목마다
   - 🔴 필수 / 🟡 검토 필요 / ⚪ 해당 없음
   - 판정 이유(사양의 어떤 값 때문인지)
   - 근거 법령·고시와 링크 (judgment-criteria.md 6절의 링크만 사용. 조문 링크가 있으면 조문으로, 없으면 법령 링크로)
   - 의무 주체(제조·수입사 / 사용 사업주 / 운영자)와 생애주기(① 제조·출시 ② 설치 ③ 운영)
   를 적는다. ⚪도 이유를 남긴다.

5. **교차 판단**
   judgment-criteria.md 5절 체크리스트를 모두 확인하고, 법령이 겹치거나 비는 지점을 별도 섹션으로 쓴다.

6. **보고서 작성**
   `report-template.md`의 형식대로 작성한다.

## 지켜야 할 것

- judgment-criteria.md에 없는 조문 번호, 수치, 기관명, 절차를 지어내지 않는다. 판단기준에 없는 쟁점이 보이면 "판단기준 범위 밖"으로 표시하고 확인 경로만 제안한다.
- [확인 필요] 표시가 붙은 내용은 결론처럼 쓰지 않고, 보고서의 "확인 필요 목록"으로 모은다.
- 근거 수준을 섞지 않는다. 판단기준에 적힌 내용은 그대로 판정하고, 판단기준에 직접 근거가 없는 해석·사업적 시사점·설계 대책 제안은 문장 앞에 **💡추론** 또는 **💡제안**을 붙여 구분한다. 판단기준에 없는 사실(어느 인증에 무엇이 포함되는지 등)은 단정하지 말고 [확인 필요]로 돌린다.
- ISO 등 유료 표준은 번호만 언급하고 내용을 단정하지 않는다.
- 링크는 judgment-criteria.md 6절에 있는 주소만 쓴다. 주소를 추측하거나 조합해 새로 만들지 않는다. 6절에 링크가 "없음"인 자료는 이름과 확인처만 적는다.
- 판단기준의 기준일을 보고서에 적고, 이후 개정 여부 확인을 권고한다.
- 이 보고서는 사전 점검용이며 법률 자문이나 인증기관의 판단을 대신하지 않는다는 문구를 보고서 끝에 한 번 넣는다.
